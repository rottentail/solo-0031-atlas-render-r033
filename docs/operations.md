# 运行与恢复

生产启动前构建 `go build -o atlas ./cmd/atlas`。通过ATLAS_STATE指定独立可写状态路径，通过ATLAS_ADDR指定受信环境的监听地址。状态目录应由运行进程拥有；临时写文件与最终文件位于同一个目录。

同一状态路径的第二个进程会因为独占文件锁拒绝启动。锁文件可长期存在，锁的有效性由操作系统进程锁决定。不要通过删除锁文件启动第二个写进程。

SIGTERM或中断信号会停止领取任务，取消执行中的计算，等待HTTP请求和执行循环结束。执行中的任务保留running，下一次启动会重新入队。SIGKILL恢复用 `python3 scripts/walkthrough.py --workflow recover-render` 演练；只会结束该脚本自己启动的实例。

备份时先正常停止实例，复制状态JSON及其同级结果目录（`<状态文件>.results/`）；恢复时向空的独立状态路径复制两者，再启动。不要把运行中手工编辑过的JSON直接作为新事实。启动校验拒绝不支持版本、损坏摘要、孤立关联和非法文档；每个存活结果还会按SHA-256重新核验结果目录中的blob，缺失或不一致时拒绝启动，避免对外发布没有字节的结果。状态JSON（版本2）不再内嵌PNG；首次用新版本打开旧的版本1状态时，会把其中存活结果的内嵌字节迁移进结果目录并重写状态，已清理（purged）记录保持无字节迁移。备份需同时包含结果目录与全部快照引用闭包，无需从外部素材服务恢复。

容量观察入口是GET /v1/status。它报告结果目录中仍被存活结果引用的blob占用字节（相同输出共享blob，只计一次）和各任务状态数量，不代表堆内存峰值。状态JSON不再随结果数量膨胀；长期积累仍会增加状态事务成本，结果目录则按独立文件增长。当前未提供任务或快照删除；部署应按预期数据量规划状态盘和实例周期。结果清理入口仅释放PNG字节：状态先在事务中转为purged，再删除没有任何存活结果引用的blob，因此并发下载或其他任务共享的相同字节不会被误删。启动会清扫崩溃遗留的无引用blob和 `.atlas-result-*` 临时文件。历史事件超过500条会截断，但sequence继续增加。

故障时保留当前状态文件和服务日志，在副本上检查。500表示事务未能完成；客户端可先读取原请求目标确认状态。提交任务时使用稳定幂等键，不能因为连接中断盲目换键。409应结合当前场景revision、快照state或收据语义判断。410说明成功结果字节已清理，任务成功事实仍保留。

`deploy/atlas.service` 是Linux systemd配置示例，需按实际用户、二进制和状态路径调整。macOS可直接运行同一二进制。当前未验证容器部署、跨进程共享写入、跨机器文件系统锁或网络存储。
